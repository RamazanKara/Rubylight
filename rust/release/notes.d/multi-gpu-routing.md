# Multi-GPU routing
- **A PC with an iGPU beside a graphics card of the same make streams on the card.** With Graphics card on Automatic, a Ryzen desktop whose integrated GPU is enabled next to a Radeon card, or a laptop with a Radeon iGPU and a Radeon card, used to render the virtual display and test its encoders on whichever GPU Windows listed first, often the iGPU, which reports fewer codecs (no AV1 on a Ryzen desktop's iGPU) and encodes slower. Rubylight now takes the GPU Windows ranks first for performance (external, then discrete, then integrated), then the one with the most video memory, and a console warning names it whenever that is not the GPU Windows lists first, with where to choose another. A display connected to an AMD or NVIDIA GPU still streams from that GPU, a PC with one GPU is unchanged, and a GPU chosen under Graphics card always wins.
- **Zero-copy capture of the virtual display stays on the GPU that renders it.** Capture now opens on the GPU the Rubylight display renders on, found the same way as the display's own GPU, so a hybrid laptop no longer drops from direct driver push to WGC over a GPU mismatch. After a display driver restart or a GPU reset the display asks for its GPU again under the GPU's current identity. A GPU chosen under Graphics card that is unplugged, disabled or not taken by the display driver now shows a console warning that names it and says what to do, and Rubylight never moves the stream to another GPU on its own.
