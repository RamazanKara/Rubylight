# Frame Warp
- **Frame Warp: camera turns on the next refresh.** For a Nightjar client that turns Frame Warp on, Rubylight learns each game while you play (how far the picture moves per mouse count and per second of right stick, how long the game takes to show an input, and where its HUD is) and tags every frame with the input it shows, so Nightjar shifts each picture by the turn the game has not drawn yet and leaves the HUD in place. What a game taught it is kept for its next session. The host setting `frame_warp` (on by default) lets clients use it; nothing runs until a client asks. Measured on the RX 7900 XT with a test game that takes 50 ms to show a turn, streamed at 2560x1440 and 60 fps: the model locked 0.6 s after the first picture, and over two runs Frame Warp took the picture's distance from where the mouse said it should be from a median of 64.9 px to 1.4 and 2.2 px (p95 184.2 to 10.6 and 13.4 px), 96% of it removed. Its GPU passes take 0.14 to 0.16 ms a frame (median) from 1080p to 4K, and the time from present to send did not change.
