- **Setup on a busy PC.** Setup's driver steps (USB/IP, the virtual display) now run as SYSTEM at normal priority. Windows ran them below normal with low I/O priority, so on a loaded PC the USB/IP checks took about 11 minutes where they take seconds. A step that is still running at setup's deadline is reported as still going on in the background, not as "could not be set up".
- **Display recovery on a busy PC.** Stopping a stalled display recovery helper no longer fails because Windows took longer than 100 ms to end it; the host waits up to 2 s after killing it.
- **File transfer on an administrator host without the desktop.** When Rubylight runs with administrator rights and the Windows desktop shell isn't running, file transfer now says so and how to fix it (start Rubylight without administrator rights, or use the Windows service) instead of answering with a generic error. It still never writes with administrator rights in place of the user's.
- **Connecting from an address a roaming device left.** After a device roamed twice, another connection from the address it roamed on from now connects at once instead of being dropped until the roamed stream ended. The address the device launched from still waits for that stream, since the roamed stream is still known there.
