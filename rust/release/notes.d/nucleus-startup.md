# Nucleus Co-op
- Background streams with Rubylight's own Nucleus Co-op handler now find the game in Nucleus Co-op's list. Rubylight added it to a list Nucleus Co-op 2.4.2 never reads, so Nucleus Co-op showed an empty list and the stream hung at its start ([#59](https://github.com/RamazanKara/Rubylight/issues/59)). The entries left in that unused list are removed.
- A background stream through Nucleus Co-op no longer waits at its start for a question nobody at the PC answers. For the session, Rubylight turns off Nucleus Co-op's install-folder check, its reminder of the End key, and its favourites-only and game-type list filters, which could hide the game. Your own choices come back when the session ends, also after a host crash.
- A Nucleus Co-op Settings.ini with keys missing, such as the short one earlier Rubylight versions wrote when the file was gone, is completed from Nucleus Co-op's own defaults instead of stopping Nucleus Co-op with a message nobody sees. Settings with letters such as ü no longer stop every background stream. A Settings.ini saved as Unicode (UTF-16) is left as it is, and the stream says to save it as ANSI or delete it.
- When Nucleus Co-op still doesn't start the game, the stream says why: the message it shows on the PC's screen, that it doesn't list the game, that it shows no profile Rubylight, or that it showed no window, with the error it logged if there is one.
- Rubylight adds a game without a hub handler only to the Nucleus Co-op it installs, whose game list it knows. With `nucleus_path` set to your own Nucleus Co-op, a background stream of such a game says to add its handler from the hub or clear `nucleus_path`.
