# Self-repair
- **An update that stopped early no longer hangs in the console.** If Windows restarted or setup was closed after an update began but before it changed any file, the console kept showing the update as installing and an automatic update's failure was never reported. The service now marks such an update as failed when it starts, with a note that the installed version still runs and that you can start the update again from Updates.
- **The virtual gamepad driver repairs itself too.** The service already set the virtual display driver up again when it went missing; it now watches the virtual gamepad driver the same way, and each driver keeps its own once-a-day limit, so one that keeps failing never holds the other back. A driver you left out at install (`--no-display-driver`, `--no-gamepad-driver`) is left out.
- **`rubylight-setup.exe --repair`.** One command repairs an installed Rubylight: it starts the service again if it is stopped or not answering, sets both drivers up again from the installation and puts back the Windows Firewall rule and the Start menu shortcut, then lists what it did. `--repair-drivers --now` now sets up both drivers; add `--driver display` or `--driver gamepad` for one.
