# Controllers when the gamepad driver refuses the host
- **When the virtual gamepad driver stops accepting the host's connection, Rubylight reconnects to it instead of failing every request.** After a reboot on some PCs, the driver refused every controller request with 0x80070006 about half a second after a controller connected; the host kept asking about 118 times a second until it restarted, and the console blamed the gamepad profile (issue #138). Rubylight now closes the refused connection and opens the driver again a second later, without waiting for input, and connects each controller again as the same controller type, in the same order. From the third refusal without a minute of working controllers in between, it waits at least 10 seconds before each new attempt, and the console names the driver and suggests restarting the Vibeshine Virtual Gamepad device or running setup again. After the fifth, until the next stream or game launch starts, it tries again only when a controller is used and at most once a minute, and the console says so. A driver whose device has gone missing is not counted as refusing and is still tried every 10 seconds. Whether a new connection keeps working on an affected PC has not been reported yet.
