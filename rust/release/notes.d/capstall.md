# Stream and game tracking
- **The stream no longer waits for the host's game checks.** Once a second the host reads the PC's process list to see whether a Steam game it launched is still running (8 ms on an idle PC, 25-43 ms when it reads the paths of newly started programs), and once per launch to tell whether a fullscreen game an Epic, Xbox, EA, Ubisoft or Battle.net client started is the app's. The stream and input threads could wait behind those reads while a game was loading; now the reads run on other threads and the stream never waits for them. The launch hitch seen once in an earlier test (up to 285 ms) did not recur on either build in our check: Pioneers of Pagonia launched through Steam by the host on the RX 7900 XT (AV1 1080p120, 60 s from launch through the fullscreen switch) had a largest send gap of 19 ms on 3.0.0-rc.5 and 51 ms with this change (the 50 ms repeat while the game drew nothing), and host processing p99 of 1.55 and 1.57 ms.
- The host log now names a stream thread that stops before claiming a picture after 150 ms (or two frame periods at very low frame rates) instead of 500 ms, with the game check as its own step.
