# Background mode follow-ups (#59)
- **Background games play only on the client.** In background mode and with game-only audio, the game's sound played on the PC's speakers as well as on the client. The game now plays on a virtual playback device nobody hears (Steam Streaming Speakers, or the virtual sink set in Audio settings) while the client still gets it. When Rubylight closes the game (the session or app ends), the game goes back to its own device first. A game left running after a disconnect keeps playing on the virtual device until it is started again, and one that quit by itself or outlived a host crash goes back the next time it runs. Nothing else on the PC changes device. In background mode the game moves as soon as Nucleus Co-op starts it, before its window shows. Windows doesn't move sound a game has already started, so a game that starts its sound before Rubylight moves it keeps playing on the PC until it is started again; the stream says so, as it does when there is no virtual playback device.
- **Games that refuse Nucleus Co-op's input hooks start again.** Without hooks (Assassin's Creed IV Black Flag Resynced), Nucleus Co-op stayed on its setup screen because it no longer listed the controller. It lists it again, so Rubylight's profile can start the game.
