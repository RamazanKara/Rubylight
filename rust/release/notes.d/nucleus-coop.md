# Nucleus Co-op
- **Background streaming with Nucleus Co-op (Experimental).** A background stream now runs the game as its own Nucleus Co-op instance and captures that window alone, away from your monitors, so the PC's displays, layout and focus stay with you. Nucleus Co-op is the only background mode: there is nothing to choose, and a `background_mode` line an earlier build wrote reads as Nucleus Co-op, which the log says once. Each game needs a Nucleus Co-op handler; a game without one, or a PC that cannot run Nucleus Co-op, refuses the background launch and says why instead of streaming your monitors. Only the device that started a background stream returns to it. Controllers only: this device's keyboard, mouse, touch and clipboard are off. **Play in the background** and **Stream in the background** keep asking for a background stream.
- **Split-screen co-op through Nucleus Co-op (Experimental).** A game that Nucleus Co-op has a handler for, and that you added in Nucleus Co-op once, gets a second library entry, "Co-op (Nucleus): <game>". Launching it starts Nucleus Co-op with one game instance per player; each device that launches it next takes the next free slot and streams its own instance, with its controller driving only that player. Stock Moonlight sees the entry like any app; a host without a handler lists nothing new.
- Rubylight downloads Nucleus Co-op 2.4.2 at the first co-op launch, checks its size and checksum, and installs it into a folder only Administrators can change. **Nucleus path** points at your own copy instead. Co-op needs the host to run as the Windows service, on a Windows build that can capture a single window; otherwise the console says why and no co-op entries show.
- Each player's stream shows only their own game window at the device's stream size, plays only that instance's audio (Windows build 20348 or newer; older builds say so on the stream) and sends rumble back to that device. Keyboard, mouse and a second controller never reach the PC's desktop: the stream says once that they are not used. The clipboard stays the PC user's. A window that closes is said on the stream, never replaced by the desktop; when the game crashes or the session ends, every player's stream ends with the reason.
- Only the device that started a session may play by default: turn on **Join co-op** for a device in the console to let it take a free slot.
- A device that disconnects keeps its slot for two minutes and gets it back when it launches the entry again. A launch that fails, expires or is replaced counts as a disconnect right away.
- The console's Nucleus Co-op panel under Maintenance shows whether background streaming can run and why not, Nucleus Co-op's install, and each session with its players. **Kick** removes a player and ends their stream; **End** stops Nucleus Co-op and every player's stream.
- A co-op launch that cannot run says why on the device: Nucleus Co-op could not be installed or started (503), no handler for the game (404, with a pointer to Nucleus Co-op's handler hub), or another session runs, the session is full, or the device may not join (409).
