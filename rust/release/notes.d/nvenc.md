# NVENC
- **NVIDIA GPUs stream again (Experimental).** Rubylight encodes with NVENC on NVIDIA graphics cards: H.264, HEVC, and AV1 where the card's encoder offers it, with HDR, HDR10+, HDR Vivid, Dolby Vision and 4:4:4. Setup and the host accept NVIDIA. With the encoder set to automatic, the host picks NVENC or AMF from the graphics card that captures. Intel graphics stay on Rubylight 2.6.x.
- NVENC keeps frames within the same frame cap as AMF. An oversize scene cut is encoded again as a keyframe, so it keeps its error correction. With slice delivery on, a large picture's slices leave as they finish.
- NVENC encodes from the compute-queue colour conversion on a D3D12 session (NVIDIA driver 522.25 or newer) and takes encoder focus from it. The startup focus check needs driver 531.61 or newer.
- On NVIDIA the host runs at realtime GPU priority, so encoding keeps up with a game that fills the GPU. This applies with hardware-accelerated GPU scheduling on, unless you turn off Realtime GPU priority with hardware scheduling (`nvenc_realtime_hags`) in the NVIDIA NVENC settings. Without administrator rights the host runs at high priority and the log says so.
- If Rubylight 3.0 to 3.2.1 changed your encoder setting from NVENC to AMD AMF, set Encoder back to Automatic to stream from an NVIDIA card. Those releases also removed the NVENC settings, so set them again.
