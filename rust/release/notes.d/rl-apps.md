# Apps
- **One exit timeout for every app.** Settings → Library → App behavior (Advanced) sets how long the host waits for an app to close before ending it, 10 seconds unless changed. An app's own exit timeout still wins. Games the Playnite sync added now follow it too: the sync no longer writes 10 seconds into each one (#71).
- **Game settings per device.** List a game's own settings files in its app (Game settings per device; `%LOCALAPPDATA%` and other Windows variables work), and each device keeps its own copy: the TV its 4K settings, the handheld its 1080p ones. When a device starts the game, the host keeps the PC's files and puts that device's copy in place; when the game closes, the files are saved as the device's copy and the PC's own come back. A device's first launch keeps the files as they are and saves them for it at the end. The editor shows which devices have a copy. A missing or locked file stops the launch with the reason. While the game is still running after the app stopped (a launcher kept it open, the host restarted), nothing is put back until it closes, or until you press Put back now in the app's editor; files that cannot go back yet show a warning in the console and are put back as soon as they can. The last three PC files put back stay as backups in the host's config folder. A file cannot be both a managed game file and a per-device settings file: such a launch says so. The host does not find a game's settings files by itself yet (#72, #69).
