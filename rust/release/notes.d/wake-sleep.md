- **Wake-on-LAN that finds the right adapter.** `/serverinfo` now reports the MAC of a physical adapter even when a client reaches the PC through Hyper-V/WSL, ZeroTier or Tailscale, preferring a wired adapter on the same subnet over Wi-Fi (Wi-Fi wake is Experimental). Paired devices with List, View or Launch can read every physical adapter's MAC, broadcast addresses and wake settings from `GET /api/native/v1/wake` (see `docs/privacy.md`).
- **Wake-on-LAN readiness and fix in the console API.** `GET /api/power` checks each physical adapter ("Allow this device to wake the computer", "Wake on magic packet", "Only allow a magic packet to wake the computer") and the PC's sleep states and Fast Startup. An administrator's `POST /api/power/wake/fix` applies exactly the listed changes (sent back as `changes`, it applies only those); it is refused while a stream is active or starting and when the adapters changed since the check. Changed adapters restart, so the network drops for a few seconds.
- **Optional Wake-on-LAN step in setup.** Unchecked by default and named per adapter; an update neither asks again nor re-applies unless `--wake-on-lan` is passed.
- **Sleep after idle** (`sleep_after_idle_minutes`, off by default, 5 to 1440). The host puts the PC to sleep (S3) only when no stream, launch, teardown, update or console use happened for that long, nobody used the PC's keyboard or mouse, and no app keeps Windows awake; it checks everything again right before sleeping. A suspended session or a launched app keeps the PC awake unless `sleep_while_suspended` is on. Modern Standby PCs show it as unsupported. Sleep PC from a client works as before.
- **Wake grace.** After the PC wakes, it stays awake for up to 5 minutes while a paired device is connecting, so Windows' 2-minute unattended sleep doesn't put it back to sleep while you browse the library.
