# Phase 1: AMD workarounds below the support floor

Audit of `claude/amd-only` at `94092342` (Remove the Windows 10 code paths). Read only; nothing in the tree was changed. Line numbers are at HEAD. While I worked, uncommitted edits appeared in the working tree that move `encoder_policy.rs` lines after 22 down by 16 and `state.rs` lines after 250 down by 12.

## The floor

- GPU: AMD RDNA 2 and newer. That means Radeon RX 6000 cards and RDNA 2 APUs such as the Radeon 680M (VCN 3: H.264 and HEVC, **no AV1 encode**), plus RDNA 3 (RX 7000, 780M/890M, VCN 4) and RDNA 4 (RX 9000, VCN 5).
- Driver: an AMD driver recent enough to support those GPUs.
- OS: Windows 11 build 22631 or later.
- Below the floor: RDNA 1 (RX 5000, Navi 1x, VCN 2), Vega (Ryzen 2000-5000G, Renoir, Cezanne, Picasso, Raven; VCN 1/2), Polaris (RX 400/500, VCE 3.x/4), GCN and older, and drivers too old for RDNA 2.

## Method and result

I grepped rust/core, rust/windows, rust/host, rust/setup, rust/web/src and rust/vulkan-layer (there is no `scripts/` directory) for generation names (RDNA, Navi, Polaris, Vega, GCN, Ellesmere, Baffin, Renoir, Cezanne, Picasso, Raven, RX/R7/R9 model numbers), engine names (VCN, VCE, UVD), APU/iGPU, Smart Access, driver-version and AMF-version terms, pre-analysis, HQVBR, QueryTimeout, "workaround", "older" and "fallback". I also read the comments in amf.rs, amf/*.rs, encoder_policy.rs, encoder_backlog.rs, compute.rs, gpu_color.rs, capture*.rs, telemetry.rs and pyrowave.rs. The same terms were grepped in rust/PERFORMANCE.md, rust/PERFORMANCE_WORK.md, rust/RELEASE_NOTES.md, docs/ and the git history.

**No workaround in scope is shown to exist only for hardware or drivers below the floor, so no row is marked `remove`.** The code never branches on a GPU generation, a PCI device ID, a driver version or an AMF runtime version. AMF is initialised against the bundled SDK version, and the only vendor test is `VendorId == 0x1002`. Every AMD-specific workaround cites an RX 6800 XT (RDNA 2), RX 7900 XT (RDNA 3) or RX 9070 XT (RDNA 4), an AMF bug that still reproduces on RDNA 3, or a decoder or client limit. Some tolerances say "older drivers" without naming a GPU or driver; those are marked keep, as the brief requires.

The only below-floor GPU named anywhere in the in-scope code is in a test comment: Radeon R7 M370, issue #28 (row 33). Below-floor handling that does exist (Vibepollo#356/#365, "older VCE runtimes") lived in the deleted C++ backend `src/amf/amf_d3d11.cpp`; nothing in the Rust tree is traced back to it.

Out of scope and not listed: vendor gates and NVIDIA settings (for the non-AMD cleanup), Windows-version fallbacks such as `display/color_state.rs` (the Windows 11 colour API) and the legacy Desktop Duplication call in `capture.rs:607-631`, and fallbacks in Rubylight's own display, gamepad and audio drivers.

## Result

No AMD workaround was removed for being below the RDNA 2 floor: none is shown to apply only to RDNA 1, Vega, Polaris, GCN or drivers too old for RDNA 2, and the RDNA 2 handling (missing AV1 encode, VCN 3, RX 6000 colour-range quirks) stays. The codec probe still advertises AV1 only where AMF creates and runs the AV1 encoder (row 35).
