# Controllers and input
- **Xbox 360 (ViGEmBus) rumble arrives at once and stops when the game stops it.** Each rumble change is forwarded as soon as ViGEmBus reports it instead of at the next 8 ms poll. At 500 changes a second all 3000 got through in a median 0.065 ms; before, about a quarter got through at 6.6 ms, and the final stop could go missing and leave the motors running.
- **Rumble no longer piles up.** Each poll takes every report a virtual pad has waiting and forwards the newest, so a game that changes rumble faster than 125 times a second doesn't build a backlog. A DualSense or DualShock 4 keeps its lightbar and trigger effects when a rumble-only report follows in the same poll.
- **A pinch is one touch frame.** All moving fingers of a pass reach Windows together: a two-finger pinch took 28 to 34 µs per pass instead of 49 to 145 µs, in one injection instead of 2 to 4.
- **USB DualSense, Steam Deck and browser input threads run at input priority,** like the stream's own input thread.
- **The control thread no longer waits on display lookups.** Input is applied before other housekeeping, the device-drawn cursor's display scale is looked up on a thread of its own, and control packets no longer copy the settings each time.
- **Input timings in the host log.** The 5 s `stream timings` line adds `input_receive_to_injected_ms` (p50/p99/max from reading a pass's first packet to its input reaching Windows) and `input_passes`, and a `gamepad timings` line every 5 s while pads are plugged shows queue times, queue depth and feedback polls. Mouse input over a loopback stream read a median 0.14 to 0.15 ms.
- **`gamepad_feedback_fast_poll`** (default off) polls the pads every 2 ms for 250 ms after a change: a VHF pad's rumble median fell from about 4.6 to 1.6 ms, at about twice the gamepad thread's CPU.
- **`absolute_left_release_delay`** (milliseconds, default 10) sets how long a left release waits after absolute mouse, touch or pen input, so a long press can right-click; 0 releases at once.
- Experimental: **`gamepad_driver_host_priority`** (default off) runs the Windows process that hosts the gamepad driver at high priority while a VHF pad is plugged in, so a busy PC delays controller input less. Other drivers in the same process run raised too; the host log names them.
