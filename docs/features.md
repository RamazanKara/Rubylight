## Video and encoding

- **AMF on Radeon.** H.264, HEVC and AV1 from AMD's hardware encoder, driven directly, with per-codec defaults tuned from VMAF measurements. The host encodes a test picture in each codec at startup and offers only what the driver delivers. A bitrate above what the driver accepts runs at the driver's ceiling, and the stream's warnings name both rates.
- **NVENC on NVIDIA.** H.264, HEVC and, where the GPU's encoder offers it, AV1, with the same stream features as AMF ([NVENC](nvenc.md)). The host refuses a codec the driver does not list before the stream starts. With variable bitrate, **Peak bitrate** sets how far the encoder may go above the stream bitrate on busy scenes, from 1× to 3× (1.5× by default).
- **GPU compute.** Frame copies, colour conversion and scaling run on D3D12 compute queues alongside the game's graphics work, so neither waits on the other ([Architecture](architecture.md)).
- **HDR end to end.** 10-bit BT.2020 PQ through HEVC and AV1 with HDR metadata in the keyframes, and 10-bit SDR for clients that request it.
- **Dolby Vision, HDR10+ and HLG.** HDR streams carry per-scene brightness statistics measured on the GPU while the frame encodes, so the display tone-maps each scene rather than one fixed peak. Dolby Vision on HEVC (profiles 8.1 and 8.4) and AV1 (profile 10.1); HLG for displays that only show HLG, PyroWave included. Other clients receive HDR10 ([Configuration](configuration.md#capture-and-video)).
- **Windows HDR Calibration profiles** on virtual displays, when enabled.
- **Full colour (4:4:4).** PyroWave, a wavelet codec, carries 4:4:4 and 10-bit HDR 4:4:4 over a fast local network. For Nightjar, **Full chroma** packs each 4:4:4 frame into an ordinary HEVC or AV1 picture. On an NVIDIA GPU whose encoder reports 4:4:4, a client's YUV 4:4:4 option gets native 4:4:4 in H.264 (8-bit) and HEVC (8- and 10-bit); the host tests each mode at startup and the checks under **PC details** on **Home** list the ones it offers. Nightjar for Windows decodes HEVC 4:4:4 in hardware on GPUs whose decoder supports it.
- **Stream presets.** **Lowest latency**, **Balanced** and **Reference quality** fill in the encoder settings you have not set yourself, for the host, one device or one app ([Configuration](configuration.md#stream-presets)).
- **Frames timed to the device's screen.** With Nightjar, the host times each frame to arrive just before the device's screen refreshes (phase lock), and finds the refresh again after the PC was busy. Games capped at the stream's frame rate go out as they arrive ([Configuration](configuration.md#picture)).
- **Frame Warp.** With Frame Warp on in Nightjar, a mouse or right-stick camera turn shows on the device's next screen refresh, and the game's HUD stays in place. The host learns, for each game, how far the picture moves per input and how long the game takes to show it, and tags every frame with the input it shows. On a test game with 50 ms of delay, it removed 96% of the picture's distance from where the mouse said it should be; its GPU passes take 0.14 to 0.16 ms a frame from 1080p to 4K. **All settings › Picture › Frame pacing › Let devices use Frame Warp** (`frame_warp`, on by default) lets clients use it ([Frame Warp](frame-warp.md)).
- **Frame limits through RTSS.** RivaTuner Statistics Server caps games at the stream's frame rate on virtual displays, or on every stream, for the host, one device or one app. **RTSS limit mode** chooses asynchronous, front edge, back edge or NVIDIA Reflex limiting; a host that streams with an NVIDIA GPU uses Reflex by itself for virtual-display streams and frame-generation games ([Displays and RTSS](configuration.md#displays-and-rtss)).
- **VRR-aware capture.** Under variable refresh the host waits for the game's next frame when it is about to arrive: for a 120 Hz game in a 60 fps stream, the picture reached the encoder 0.25 ms old instead of 4.68 ms ([measurements](performance.md#vrr-capture-age)). A 1000 Hz VRR mode serves clients that request it.
- **Encoder focus** (off by default). Static regions such as a HUD, text or an editor get a larger share of the bitrate than moving ones ([Configuration](configuration.md#encoder-focus)).
- **Slice delivery.** H.264 and HEVC frames of 4K-size pictures go to the network slice by slice while the encoder finishes the rest; a 4K60 HEVC picture arrived 1.2 to 1.5 ms sooner. Smaller pictures, where it measured no gain, go out whole. `video_slice_delivery` sets it ([design](b2-slice-delivery.md)).
- **Large frames leave block by block.** Each error-correction block of a large frame is sent as soon as it is built: at 4K60 the first packet left about 0.55 ms sooner on HEVC and AV1 (`video_send_early_blocks`, on by default).
- **Beam-raced PyroWave.** A client that requests it receives each PyroWave frame in display order, so Nightjar on the desktop decodes and presents the top of the picture while the bottom is still arriving ([article](beam-racing-pyrowave.md)).
- **RTX HDR and RTX Video enhancement** (NVIDIA build). Rubylight's separate, unsigned NVIDIA build runs NVIDIA's RTX HDR, which turns an SDR game into HDR for an HDR stream while the display stays in SDR, and RTX Video enhancement, which cleans up and sharpens the picture at the stream's own size, on a GeForce RTX card before encoding. Both are off until the host or an app turns them on; each app has its own values, and Nightjar can turn either on or off for one PC ([Configuration](configuration.md#rtx-hdr-and-rtx-video-enhancement), [NVENC](nvenc.md#rtx-hdr-and-rtx-video-enhancement)).
- **Neural Rendering.** A switch on a game's page installs a third-party neural upscaling mod into games with DLSS, FSR or XeSS, and removes it again. It needs RDNA 3 or RDNA 4 graphics with 12 or more compute units and AMD Software 26.9.1 or newer ([Configuration](configuration.md#neural-rendering)).
- **Hardware color conversion** (off by default). On AMD AMF, the driver's video converter can convert and scale YUV 4:2:0 frames in SDR, HDR10 and HLG instead of Rubylight's shaders, handing its output to the encoder without a copy; other frames keep the shaders ([Configuration](configuration.md#amd-amf-encoder-settings)).
- **Aspect ratio and scaling.** A source of a different shape is letterboxed. Streams below the desktop's resolution are downscaled with an area-averaging filter, which reduces shimmer on thin lines.
- **Per-frame timing record.** With `BUTTERPOLLO_TIMING_RECORD` set, each video stream writes capture, convert, encode, packetize and send times on one clock, ready to join with a client's frame log ([Timing record](timing-record.md)).

## Network resilience

- **Scene cuts without freezes.** A scene cut too large for its error correction is encoded again as a keyframe that fits. With 0.3 % random loss on a 250 Mbps HEVC stream, freezes after scene cuts went from 15 to 0. Recovery keyframes keep their full error correction within Moonlight's four FEC blocks.
- **Recovery without a keyframe.** A short loss on H.264, HEVC or AV1 is repaired with a frame that references an older picture the client still holds, for every client. When the host's own network adapter briefly refuses packets, the host sends a keyframe at once instead of waiting for the client to ask. Long-term references can be turned off for one device whose decoder freezes on them (**Devices → Encoder overrides**).
- **Link-rate adaptation.** When a client loses frames that error correction cannot repair, the host steps the bitrate down to what the link delivered, shows this on the stream card, probes back up and returns to your rate after ten clean seconds. PyroWave also backs off when frames are lost while sending. A link that carries the stream is unaffected ([Configuration](configuration.md#lower-bitrate-when-the-link-cannot-carry-it)).
- **Congestion control from packet arrivals** (off by default). A client that reports when each video packet arrived, such as Nightjar, lets the host see a queue building on the way before packets are lost: the host lowers the bitrate to just under what arrived, paces video at the bottleneck's rate and climbs back when the delay settles. It works together with link-rate adaptation, the lower bitrate winning ([Configuration](configuration.md#adapt-to-network-congestion)).
- **Wi-Fi pacing.** Clients that report Wi-Fi or mobile data are paced adaptively from the first frame; on 2.4 GHz Wi-Fi, unrecoverable frames per run fell from 61 to 15.7. Adaptive pacing can also be turned on for every stream ([Configuration](configuration.md#capture-and-video)).
- **Client-chosen error correction.** A client that supports it chooses its own share of recovery packets, or lets the host follow its loss reports, up to `fec_max_percentage`, and can test the link before choosing its first bitrate ([Configuration](configuration.md#error-correction-chosen-by-the-device)). Error correction uses GFNI instructions on processors that have them (AMD Zen 4, Intel Ice Lake and newer), with the same bytes.
- **Changes without reconnecting.** A Rubylight client can change the stream's resolution, bitrate and frame rate mid-stream, as a foldable phone does when it is opened ([Control messages](control-messages.md)).
- **Play over the internet.** Automatic port forwarding asks the router through UPnP, PCP or NAT-PMP and opens IPv6 pinholes, and the console shows each port mapped or refused and why. Where no port can be forwarded, such as behind carrier-grade NAT, Nightjar reaches the PC over a direct path both sides punch through their routers, found through public STUN servers and the BitTorrent DHT with encrypted records, without any server of ours ([Play over the internet](internet-play.md)).
- **Roaming.** A client whose address changes, such as a phone moving from Wi-Fi to mobile data, keeps its stream ([Configuration](configuration.md#roaming)). Control messages are resent as soon as the client is heard from after an outage.
- **Prioritized stream traffic.** Video and audio for devices on the local network carry DSCP marks, so Wi-Fi sends them ahead of other traffic; a switch turns the marks off for a router that mishandles them ([Configuration](configuration.md#prioritize-stream-traffic-dscp)).
- **Host bitrate adaptation** (off by default). For conventional Moonlight streams, the host adapts the bitrate to observed loss, accounting for FEC and audio, and yields to the client's own bitrate control ([Configuration](configuration.md#host-bitrate-adaptation)).

## Capture

- **Frames from Rubylight's display driver.** On its virtual displays, the driver hands the host each frame Windows composes with no capture API in between, and on Radeon the frame is converted in place. **Automatic** capture uses this path; a reconnect to a static desktop receives its picture at once.
- **Windows Graphics Capture** on physical displays, and on a virtual display whose driver cannot push frames. **Desktop Duplication** takes over when WGC cannot open, and a lost Desktop Duplication session is reopened without ending the stream.
- **One app's window.** An app, or one app on one device, can stream only its own window instead of a display. The host finds it among the programs the app started, or by program name and title, keeps its shape with black bars, maps mouse and touch onto it, and follows it through resizing, fullscreen switches and moves between monitors. While it is minimised or after it closes, the stream shows the display and says why, or ends ([Configuration](configuration.md#the-apps-window-in-place-of-a-display)).
- **AMD Direct Capture.** On a display connected to a Radeon, capture can take each picture the driver presents through AMF, up to the display's refresh rate, with Windows Graphics Capture as its fallback (`capture = amd`, [Configuration](configuration.md#graphics-card-and-capture-method)). Frame generation's extra frames (AMD Fluid Motion Frames) are not streamed by it or any other capture method.
- **The lock screen and the sign-in prompt** stream too, so the PC can be unlocked from the client; capture returns to WGC when the desktop comes back. A locked virtual machine with no monitor attached streams as well ([#6](https://github.com/RamazanKara/Rubylight/issues/6)).
- **Services, virtual machines and containers.** The Windows service captures through a helper in the signed-in user's session, and the same host runs on headless machines, virtual machines and GPU-equipped Kubernetes pods.

## Displays

- **A virtual display for each device**, one shared by all devices, or none, with exclusive, extended, primary and isolated layouts, HDR, and the device's resolution and refresh rate ([Displays and RTSS](configuration.md#displays-and-rtss)).
- **Your monitors as you left them.** The saved monitor layout is restored after a stream or a crash, and **Advanced → Troubleshoot → Displays and Windows session** or a restore hotkey (`dd_snapshot_restore_hotkey`) restores it on demand. A monitor that keeps dropping its signal is left on after its third return within five minutes, instead of blanking the stream each time.
- **Client-side display choice.** A Rubylight client can request, per PC, the virtual display alone, a virtual display beside your monitors, or no virtual display, without changing the host's settings ([Configuration](configuration.md#display-choice-from-the-client)).
- **Rotation.** A device's own virtual display takes the stream's portrait or landscape orientation, and a monitor rotates to match and back after the stream; with **Match the device**, the display follows a device as it turns ([Configuration](configuration.md#displays-and-rtss)).
- **Monitors stay off while a device is away** (**Keep monitors off while paused**, off by default). With an exclusive layout, the monitors stay off while a device is disconnected, even one that wakes over HDMI, until the device returns or its display is no longer kept (**Keep a disconnected display for**). The restore hotkey still brings them back ([#56](https://github.com/RamazanKara/Rubylight/issues/56)).
- **Concurrent clients**, each on its own virtual display. **Stream here too** shares the display the running game is on, as that display is.
- **Dual screen.** Nightjar's Dual screen mode streams a second display to the same device under its one pairing: a virtual display of its own beside the game's, or the PC's other monitor when streams use physical monitors. The host puts the two displays back where they were the last time ([3.11.0](../rust/RELEASE_NOTES.md#new-in-3110), [3.11.1](../rust/RELEASE_NOTES.md#new-in-3111)).

## Audio

- **Surround** up to 7.1.4 over Opus, with endpoint matching by ID, name, description or adapter, and Steam Streaming Speakers.
- **Receiver formats.** A client that requests them receives uncompressed PCM up to 7.1.4, or Dolby Digital and Dolby Digital Plus, so a TV, soundbar or AV receiver decodes the sound itself ([Configuration](configuration.md#pcm-and-dolby-digital-audio)).
- **Night mode and headphone surround** (off by default) compress the dynamic range and render surround for headphones on a stereo device ([Configuration](configuration.md#surround-night-mode-and-headphone-surround)).
- **Game-only audio.** Captures a launched game and its child processes on supported Windows versions; when the game cannot be identified, the stream is silent and the host warns ([Configuration](configuration.md#game-only-audio)).
- **Microphone.** The client's microphone plays into Steam Streaming Microphone, encrypted in transit, with its recording level held at 0 dB or lower so it does not clip. Nightjar can also be the PC's microphone with no stream running ([Microphone](microphone.md)).

## Input and controllers

- **Keyboard, mouse, touch and pen** through Windows' input injection, and **controllers** through the signed virtual gamepad driver that the installer sets up. A whole pinch reaches Windows as one touch frame.
- **Virtual mouse and touchpad.** With the optional USB audio and haptics driver, the mouse is a virtual USB mouse polled every millisecond that games and anti-cheat read like a real one, with injection as the fallback (**Mouse input method**, per game and device too). A tablet's or laptop's physical touchpad in Nightjar reaches Windows as a precision touchpad, so two-finger scroll and three- and four-finger gestures work ([Virtual mouse and touchpad](virtual-mouse.md)).
- **A matching virtual pad.** **Automatic** gives PlayStation-type clients a DualSense with adaptive triggers, Nintendo-type clients a Switch Pro controller (a Switch 2 Pro Controller its own) and others an Xbox Series pad; Xbox One, DualShock 4 and Steam Controller can be chosen too, for the host or for one device. Controller identities persist across reconnects ([Controllers](configuration.md#controllers)).
- **Steam Controller.** The **Steam Controller** type presents a wired 2026 Steam Controller with both trackpads, back grips, grip and stick touch, motion and a battery. A client with a real Steam Controller also passes Steam's pad haptics and settings through; other clients get rumble made from those haptics, and a motor whose stop message never arrives stops after at most 10 seconds. Nightjar's on-screen controls, classic or modern, can add the trackpads, back buttons and grip touch.
- **Xbox 360 (ViGEmBus).** For tools such as reWASD that look only for USB controllers, every client can get an emulated USB Xbox 360 pad through ViGEmBus, which you install separately.
- **DualSense and Steam Deck over USB.** With usbip-win2 installed, a DualSense gets waveform haptics, speaker and headset audio and microphone input, and a Steam Deck appears as a genuine Steam Deck controller with trackpads, gyro and back grips for Steam Input ([setup and limits](dualsense-haptics.md)).
- **Switch 2 Pro Controller over USB.** With usbip-win2 installed, a Nightjar client's Switch 2 Pro Controller appears as a Switch 2 Pro Controller, with its C button, grip buttons, gyro, rumble and battery, for SDL and Steam; **Switch 2 Pro (USB/IP)** gives every controller one ([Controllers](configuration.md#switch-2-pro-controller)).
- **Motion server for emulators** (off by default). Cemu, Dolphin, Citra and other emulators read each streamed controller's gyroscope, accelerometer, buttons and touch over the DSU (cemuhook) protocol, port 26760 ([Configuration](configuration.md#motion-server-for-emulators-dsu)).
- **Haptics from game audio** (off by default). A DualSense renders the game's bass and impacts when the game sends no vibration, with strength, response and noise-gate settings that apply mid-stream ([how it works](dualsense-haptics.md#haptics-from-game-audio)).
- **Back grips.** Steam Deck L4, R4, L5 and R5 and Xbox Elite paddles press the buttons you assign.
- **On-screen keyboard follows text fields.** When a text field on the PC receives focus, Nightjar opens its keyboard, with digits for number fields and no suggestions for passwords. Keyboard layouts from the device, a client-drawn cursor, touch as a mouse or trackpad, and pen barrel roll are covered in [Configuration](configuration.md#keyboard-touch-pen-and-cursor).
- **Couch menu.** Hold L3+R3, press Ctrl+Alt+Backspace or hold the top-left corner, in any Moonlight client, for **Back to game**, **Disconnect**, **End session** and **Close game**, drawn into the stream ([Configuration](configuration.md#couch-menu)).

## Game library

- **Every installed game.** Steam, Playnite, Epic Games, Battle.net, EA app, Ubisoft Connect, GOG, Xbox and Microsoft Store games, and games in folders such as `D:\Games`, appear in one **Games** list with their covers, one switch per launcher and one **Sync now**. Every launcher has Steam's options in a group of its own under **All settings › Games** (**Epic Games options**, **GOG options** and so on): sync automatically, remove uninstalled games and games to leave out, and for Battle.net, which records when a game was played, only the recently played games. Epic Games covers come from the launcher's own catalog. Games you remove stay out until you restore them.
- **Steam.** Syncs on demand and every 30 seconds, with covers from Steam's cache or store. An install or removal reaches a client in about a minute with auto sync on; library scans run at background priority. A Steam game's stream ends when the game's processes exit.
- **Collections.** Each library entry carries its Steam collections and Playnite categories, read from Steam's and Playnite's own files without writing to them, so Nightjar can group Home by them with no setup. Missing or changed files mean no collections and one log line, never a failed library.
- **Playnite.** Library sync, launches through Playnite with the stream's environment, a **Playnite (Fullscreen)** entry, the game brought to the foreground, and **Wait after a game closes** for games that restart through a launcher ([Configuration](configuration.md#when-a-playnite-game-closes)).
- **Apps.** Commands with preparation and undo steps, detached commands, URLs and documents, an inferred working folder, start before sign-in, and one exit timeout for every app that sets none.
- **Per-game and per-device settings.** Stream, display, input and encoder settings, a graphics driver profile, RTSS frame limits and Lossless Scaling profiles, applied at launch and removed at the end ([Configuration](configuration.md#settings-for-one-app-or-device)).
- **Game settings files per device.** A game's own settings files can be kept per device, so a TV keeps its 4K settings and a handheld its 1080p ones; the PC's own files come back when the game closes ([Managed game files](configuration.md#managed-game-files)).
- **Close apps on disconnect.** An optional default closes the app when its last device leaves; each app can follow it or override it ([Configuration](configuration.md#close-apps-on-disconnect)).
- **Confirmed game switch.** Starting another game closes the running one only after the player confirms.
- **Launcher status.** When a Steam, Epic Games, EA app or Ubisoft Connect window waits for an update or a sign-in, the session reports it and a client can show it. The host only reads window titles; it never clicks or types into a launcher.

## Co-op and background streaming

- **Split-screen co-op.** A game that Nucleus Co-op supports gets a "(Co-op)" entry. Each device that starts it joins as the next player, up to four, each in its own instance with its own picture, sound and virtual controller. **Home** shows who plays in which slot, a player who steps away keeps their slot for two minutes, and Nightjar lists the sessions and joins a free slot ([Co-op and background streaming](nucleus-coop.md)).
- **Guests from other devices.** A second paired device that joins the running game becomes a guest of the device playing: the same picture and sound with an encoder of its own, its own controller as the next player, and the keyboard and mouse only if granted, one holder at a time. The player lets it in from Nightjar or the console's Home, and can change what each guest may do, kick or block it, and let guests in for a time. Stock Moonlight joins by starting the running app ([Guests from other devices](multiclient.md)).
- **Background streaming.** A device plays its own instance of a game through Nucleus Co-op while someone else keeps using the PC: the PC's displays, focus, keyboard and mouse stay with the local user, the game's sound leaves the PC's speakers, and only the device's controllers reach it. A Windows notification tells the person at the PC which device started which game. A single-player game needs no handler from the Nucleus hub; a Steam game starts through its Steam app ID and an Epic Games game with the arguments its launcher would add, while other launchers' links and games with anti-cheat are refused ([Background streams](nucleus-coop.md#background-streams)).

## Control from a client

- **Native API.** A paired client on the streaming HTTPS port can read the host's capabilities, the game library with covers and the session state. Stock Moonlight and Artemis are unaffected ([Native API](native-api.md)).
- **Nightjar as a remote console.** Nightjar opens on a Home with favourites, what is running, the library of every paired PC, and a page for each game with Play or Resume. A session menu closes the game, ends the session or changes Radeon or NVIDIA driver settings without leaving the stream.
- **Move or share a running game.** **Continue here** moves the running game's stream to the device you are holding while the game keeps running; **Stream here too** joins it on a second device ([3.7.0](../rust/RELEASE_NOTES.md#new-in-370)).
- **Session actions.** **Disconnect** leaves the game running, **End session** stops the stream and keeps the game, **Close game** also quits it ([Configuration](configuration.md#session-actions)).
- **Host control.** A per-device permission to close games, change graphics driver settings and install a pending host update, off until you enable it ([Configuration](configuration.md#host-control-for-a-device)).
- **Driver settings with restore.** A device with host control changes Radeon settings such as Anti-Lag and Radeon Chill during a stream, or on an NVIDIA GPU the driver's Low Latency Mode, Max frame rate, Vertical sync, Power management mode, texture and anisotropic filtering and Smooth Motion (driver 571.86 or newer). The host records the PC's own values first and puts them back when the session ends, after a crash too; a value it can't put back exactly is shown and left alone ([Configuration](configuration.md#radeon-settings-with-restore)).
- **A driver profile per game.** On a game's **Graphics driver** panel: **Competitive** (Anti-Lag on Radeon, Low Latency Mode at Ultra on NVIDIA), **Smoothness** (the game capped at the stream's frame rate), **Quality** (on Radeon anisotropic filtering and the driver's anti-aliasing enhancement, on NVIDIA 16x anisotropic filtering with high-quality texture filtering) or a custom list, written when the game starts and restored when the session ends, including after a crash ([Configuration](configuration.md#radeon-settings-per-game)).
- **Sleep, wake, restart and shut down.** A device you authorise puts the PC to sleep while nothing is streaming, on a PC with S1, S2 or S3 sleep, and with its own permission restarts or shuts down an idle PC after a confirmation. The console shows whether devices can wake the PC and each network adapter's wake settings, and can put the PC to sleep after a period of inactivity. The wake address sent to clients includes physical adapters behind a Hyper-V external switch, and Nightjar can keep other wake addresses for a PC, for adapters that wake it when the streaming one cannot ([Configuration](configuration.md#sleep-pc-and-sleep-after-idle)).
- **PC commands in the stream menu.** A device with the PC commands permission runs commands you set on the PC from its stream menu or the host menu. Each app can add its own, listed only while it runs, with an undo that runs when the app closes, and can hide the ones from Settings ([Configuration](configuration.md#stream-menu-commands)).
- **Commands when a device connects.** Each device can run its own commands on the PC when it starts streaming and when its stream ends, as administrator if you choose; a game can turn them off ([Configuration](configuration.md#device-connect-and-disconnect-commands)).
- **Lock when you leave.** Rubylight can lock Windows when the last device leaves, never during a stream, and the next stream unlocks it from the lock screen ([Configuration](configuration.md#lock-windows-when-the-last-device-leaves)).
- **Live hardware readings.** On request, a streaming client can show the PC's CPU load and the Radeon's usage, temperatures, power, clocks and VRAM in its overlay ([Hardware metrics](hardware-metrics.md)).

## Clipboard, files and USB

Each of these needs its permission on the device. The clipboard comes with **Everything**, which the first paired device gets; file transfer, shared folders and USB devices are always granted on their own ([Privacy](privacy.md#your-own-devices)).

- **Clipboard.** Text copied on either side is sent to the other as you copy it, and images can be copied in both directions ([Configuration](configuration.md#clipboard-files-and-usb)).
- **Shared folders.** Folders you share with a device can be browsed and downloaded from, and with a write grant uploaded to ([Configuration](configuration.md#shared-folders)).
- **File transfer** (off by default). Devices send files to the PC and fetch them back, into the signed-in user's `Downloads\Rubylight` or a folder you choose, paced while a stream runs ([Configuration](configuration.md#file-transfer)).
- **USB forwarding** (off by default). A USB device plugged into the client is attached to the PC during a stream, over USB/IP inside the stream's TLS connection ([USB forwarding](usb-forwarding.md)).

## Browsers and TVs

- **WebRTC server** (off by default). Pair a Samsung Tizen TV or a browser with a PIN and stream H.264, HEVC or AV1 with HDR, surround sound, gamepads, keyboard and mouse. The median glass-to-glass time for AV1 1080p60 was 17 ms with the browser on the host over loopback ([WebRTC](webrtc.md)).
- **A play page for TVs and consoles.** A TV, console or car browser opens `https://<PC address>:47991/play`, pairs once with a PIN and picks a game with the remote, the arrow keys or a controller ([Play in a TV browser](webrtc.md#play-in-a-tv-browser)).
- **Stream in the console.** The console's **Stream in the browser** page plays a game in the browser tab, authenticated by the console session instead of pairing: AV1, HEVC or H.264 at the resolution and frame rate you pick, stereo, keyboard and mouse ([WebRTC](webrtc.md#stream-in-the-console)).
- **Guests in the browser.** An invite link, on a guest port of its own, lets up to four friends watch the console's stream in their browsers, view only or with controller, keyboard and mouse, with an expiry, kick and revoke. One encode for everyone, no relay servers, and UPnP can forward the guest ports ([Guests in the browser](browser-guests.md)).

## Console and pairing

- **Pairing** with a PIN, a one-time PIN or a QR code that Nightjar scans, with per-device permissions and an enable switch. Pairing from the console offers **Play games** (the default), **Watch only** or **Everything**; the first device gets **Everything**. WebRTC devices, and pairings made through the API without a choice, start view-only ([Configuration](configuration.md#host-control-for-a-device)).
- **Pairing from the couch.** A paired device with **Approve new devices** enters the PIN a new device shows, so a TV or console pairs without a walk to the PC. The tray's **Pair a device** opens the QR code, and **Open in Nightjar** pairs a phone that shows the console.
- **Home** leads through pairing and playing, then shows the current stream, running co-op games, the host's own warnings and your games. **Games**, **Devices** and **Settings** cover the library, pairing and stream options; **Settings** shows the few settings most people change, and **All settings** has every other one in six tabs, with search. **Ctrl+K** finds any page, game, device, setting or common action from anywhere in the console.
- **The stream card** shows frame rate, bitrate and encoder timing together, the frame rate at each stage of the pipeline, and what the host changed and why.
- **Costly settings named.** An AMD encoder setting changed to a value that adds delay or weakens recovery says what it costs, and **Settings** lists every such setting you changed.
- **Help** has connection help, the support bundle and **Log analysis**, which reads the host log and explains the failures it recognises, such as AMD encoder hangs, lost capture, ports in use, network loss and an outdated display driver, with the corrective action ([Troubleshooting](troubleshooting.md)). **Advanced → Troubleshoot** restarts Rubylight and holds display recovery, the Windows session, Nucleus Co-op's status and crash reports.
- **Client build warnings.** The device list shows the build each device last reported and warns when that build has a known problem with this host.
- **Webhooks.** Signed events to your own URLs when devices pair, apps start and stop, streams begin and end, and the PC restarts, shuts down or updates ([Webhooks](webhooks.md)).
- **Tray icon** with notifications for pairing requests, new versions and apps starting, pausing and stopping.
- **Logs and support.** Rotating logs, a live log view, crash dumps and a one-click support bundle.
- **Connection route.** An authenticated client can check whether its Tailscale route to the host is direct, relayed or unknown, without seeing other peers ([Remote connection route](network-path.md)).

## Installation and updates

- **One installer** sets up the service, drivers, firewall rule and shortcuts, and upgrades in place. It offers usbip-win2 for Steam Deck controllers, DualSense USB audio and haptics, and USB forwarding, and can turn on Wake-on-LAN. It imports an existing Vibepollo or Apollo profile with its settings, paired devices, apps and covers, or installs alongside the other host with its own service and ports ([Getting started](getting-started.md#install-or-run-portable)).
- **Updates.** New versions are offered, not forced; automatic installation is opt-in, at an interval or a time of day you choose. The host downloads the installer from the official release, verifies its size and SHA-256 digest, waits for an idle minute and upgrades through the service. A failed copy or start restores the previous files ([Updates](configuration.md#updates)).
- **Crash recovery.** The service restarts the host after a crash.
- **Separate instances** with their own profile folders and base ports ([Multiple instances](configuration.md#multiple-instances)).
- **Settings backup and restore.** One file with the settings, apps, covers, device settings, game settings files and webhooks, from the console or the tray. Pairing identity and sign-in go in only when you choose. A restore shows what changes, saves the current settings first and restarts ([Configuration](configuration.md#settings-backup-and-restore)).

## Clients

Rubylight implements the Moonlight protocol, so Moonlight and other Sunshine-compatible clients work with it on Windows, macOS, Linux, Android, iOS, Apple TV, Android TV, consoles and handhelds. H.264, HEVC and AV1 stream in SDR and HDR wherever the device decodes them. PyroWave needs a PyroWave-capable client such as [Nightjar](https://github.com/RamazanKara/nightjar), which also uses the native API and runs on Android, Android TV, Fire TV, Windows, Linux and macOS ([releases](https://github.com/RamazanKara/nightjar/releases)). The [hardware matrix](hardware-matrix.md#4-clients) lists the clients that have been tested.

To choose a stream format, see [Getting started](getting-started.md#choose-your-stream-format).
