# One lost frame no longer lowers the bitrate
- **A client asking again for the same repair no longer lowers the bitrate.** In an AV1 stream to a Retroid Pocket 6, the client lost one frame and asked to invalidate it eleven times before the repair arrived; the host counted ten requests, called the link too slow and held 21 Mbps down to 14.5 Mbps for 26 s. Repeated requests for one loss now count once, and a client that announces FEC status (Moonlight, Artemis, Nightjar) is judged by its reports from the first frame, as the slow-pace guard already did. Separate losses still lower the bitrate.
