# Rubylight and Vibepollo 2.0

[Documentation](../docs/README.md) · [Getting started](../docs/getting-started.md) · [Configuration](../docs/configuration.md) · [Performance overview](../docs/performance.md)

**Compatibility index:** [Defaults](#deliberate-differences) · [Feature matrix](#feature-by-feature) · [Recorded evidence](#evidence) · [Reproduce checks](#reproducible-verification)

Rubylight's Rust host is meant to replace Vibepollo 2.0.0 (commit `8a8c4b03a280ab9f567beb380110abb80f5220b8`) on Windows. This file lists what matches and what differs on purpose. "Same" means the Rust host reads the same settings and files and gives clients the same answers. [Evidence](#evidence) at the end lists the hardware and clients each claim was run on, and [Where it has been tested](#where-it-has-been-tested) summarises them.

Left out on purpose: WebRTC streaming, session history and host statistics pages, the SudoVDA fallback, and Linux and macOS hosting.

## Deliberate differences

The table compares the current defaults. Since rc.9, Automatic capture prefers WGC; WGC-selected streams also use guarded source-phase pacing, while explicit Desktop Duplication keeps its previous pacing default. See [PERFORMANCE.md](PERFORMANCE.md) for measured benefits, fallback behavior and hardware limits.

| Setting | Vibepollo default | Rubylight default |
| --- | --- | --- |
| `capture` (automatic) | Windows Graphics Capture on Windows 11 23H2 and later | Windows Graphics Capture on physical and virtual displays, with Desktop Duplication fallback when WGC cannot open |
| `amd_quality` | `balanced` | `speed` |
| `frame_limiter_auto_virtual_framegen` | `enabled` (virtual display at 4x the stream rate) | `legacy` (2x); a VRR request still gets 1000 Hz |

Select **Save changes** in the console to write settings. Most saved stream settings take effect on the next stream; startup settings such as network listeners and advertised codec support need a host restart. See [configuration](../docs/configuration.md#save-reconnect-and-restart) for the current save and restart behavior.

## Feature by feature

| Area | Status | Notes |
| --- | --- | --- |
| Profile and settings | Same | Imports a Vibepollo or Apollo profile in place. The parser accepts what Vibepollo accepts (BOM, quoted and hex numbers, lists, enum spellings, `driver_decides`, `wgcc`) and logs values it ignores. An invalid `apps.json` starts the host with no apps and is kept as `apps.json.invalid`. The shared virtual display GUID in `vibeshine_state.json` is reused. |
| Per-app and per-device overrides | Same | Only Vibepollo's list of stream, input, display and encoder keys can be overridden; other keys are logged and ignored. |
| Pairing | Same | PIN and one-time PIN (`/api/otp`), pending requests in the console, per-device permissions and enable switch. |
| Moonlight endpoints | Same | `serverinfo` extras (virtual display, frame limiter, permissions, server commands), `/applist` with Vibepollo's placeholder for devices without the list permission, `/launch` and `/resume` with `VirtualDisplayDriverReady`, `/unpair` on HTTP and HTTPS, `/bitrate` capped by `max_bitrate` and 500 Mbps, ABR capability reported as client-driven. |
| Codecs and stream | Same | H.264, HEVC, AV1, HDR, 10-bit SDR, 4:4:4 where the encoder supports it, PyroWave, FEC, reference frame invalidation (AMF and NVENC). rc.6 isolates optional PyroWave capability checks in a bounded user process, so a driver/overlay crash or stall during that check cannot terminate the host. |
| Capture | Same | Desktop Duplication with recovery. Service-mode WGC uses a signed-in-user helper, avoiding SYSTEM's `CreateForMonitor` error `0x80070424`. GPU-only frame transfer and compute copies were verified through the installed service with native HDR on an RX 7900 XT. Lock/UAC selects Desktop Duplication and returning to the normal desktop retries WGC; tested by the owner on the secure desktop, and a user confirmed streaming from a locked VM ([#6](https://github.com/RamazanKara/Rubylight/issues/6)). VRR and game frame generation need a Moonlight client that requests them and a game to exercise them. |
| Virtual displays | Same | Per device, shared or off; layouts exclusive, extended, primary, isolated; HDR; permanent count (also the old `dd_vdd_static_monitor_count`). rc.6 treats `virtualDisplay=0` as no client opt-in, preserving the host policy; a positive opt-in preserves shared mode. Device-forced virtual displays take precedence over physical app output. While Windows is locked, the stream's display is set up, kept and restored from the lock screen's desktop; if the virtual display still cannot be set up there, the stream shows the physical display with a stream-card warning, as Vibepollo does (confirmed by a user streaming from a locked VM with no monitor, [#6](https://github.com/RamazanKara/Rubylight/issues/6)). A host with no active display uses a virtual display for every stream, whatever the settings say (when the driver is installed). |
| Display layout | Same | Golden layout restore (skipped while a display it names is disconnected), restore after a stream or crash, mode remapping, the display restore hotkey (`dd_snapshot_restore_hotkey`). `dd_wa_dummy_plug_hdr10` turns VSync off but does not force HDR on. |
| Device display mode | Same | A device's `display_mode` sets its display's resolution and refresh in place of the host's policies; the stream keeps the client's rate. |
| Letterboxing | Same | A source of another shape keeps its aspect ratio between black bars, in the GPU and the software encoders. |
| Input | Implemented | Keyboard (key code mask, synthetic modifiers and extended keypad Enter), mouse, touch, pen and controllers. Every pad comes from the VHF driver the installer brings. Automatic gives PlayStation-type clients a DualSense, which has adaptive triggers, Nintendo-type clients a Switch Pro and others an Xbox Series pad; explicit profiles are preserved, and ViGEmBus settings from earlier releases or imported profiles (`x360`, `ds4`) load as the VHF Xbox One and DualShock 4 (unit-tested migration). Xbox-type clients with enabled motion/touchpad selection get a DualSense. VHF also supports DualSense triggers and feedback. Controller touch packets preserve their touchpad index, but the driver exposes one surface with two contacts. A client that announced two touchpads (a Steam Deck's trackpads) gets them side by side on that surface, the first on its left half and the second on its right; a second touchpad the client did not announce is safely ignored. Keypad hold/repeat/release has automated coverage. Local DS4 and DualSense tests passed through the signed VHF driver, verifying primary multitouch and secondary-pad isolation in native HID reports. The pads have no back-grip (paddle) buttons, so Moonlight's paddles (a Steam Deck's L4/R4/L5/R5, Xbox Elite paddles) press the button or full trigger chosen under Back grips (`back_grip_*`, unit-tested mapping); unmapped grips are dropped and a press shows a stream-card hint. Moonlight's `LI_CTYPE_STEAM` can instead become a real Steam Deck controller (28de:1205) served over USB/IP on loopback and attached by usbip-win2's signed driver, so Steam on the host sees a Steam Deck with trackpads, gyro and back grips (`steam_deck_controller`: automatic while Steam runs, always, or the virtual pad; unit-tested report, descriptors and USB/IP exchange; Sunshine, Apollo and Vibepollo have no equivalent). Without usbip-win2 it gets the DualSense like other motion-capable clients, and a device named Steam Deck whose controller arrives without gyro gets a stream-card hint to disable Steam Input. On the host with usbip-win2 0.9.8.1 and no client, the controller enumerated as 28de:1205 with three HID interfaces, Steam identified a Steam Deck Controller (controller_neptune) and it detached cleanly; with Steam running, a shared HID reader got its reports every 4 ms with the probe's input and a rumble feature report reached Rubylight intact. Input was turned off in the Moonlight PC 6.2.0 streaming matrix, which tested video, audio and reconnects. |
| Audio | Same | Endpoint matching by id, name, description or adapter; Steam Streaming Speakers; surround Opus. |
| Microphone | Beyond Sunshine and Vibepollo; Apollo's format | A client's microphone plays into Steam Streaming Microphone, installed from Steam on first use, in the format of Apollo's open microphone pull request, so its clients work unchanged ([Microphone](../docs/microphone.md)). Encrypted only. |
| Apps | Same | Commands, preparation and undo, detached commands, URLs and documents, working folder inference, `APOLLO_*` variables, starting before sign-in. |
| Steam library | Same | `steam_*` settings, sync on demand and every 30 seconds, covers from Steam's cache or store as PNG, `/api/steam/*`. A Steam app's stream ends when the game's processes exit. |
| Playnite | Same | Talks to Vibepollo's Playnite plugin (shipped in the package, installed from the console). Apps with a `playnite-id` start through Playnite with the stream's environment and end when Playnite reports the game stopped; ending the stream closes the game's processes. The library syncs recent, category, plugin or all installed games with Vibepollo's rules, and the "Playnite (Fullscreen)" app opens fullscreen mode. A started game, and the fullscreen menu when it opens or comes back after a game, is brought to the front with Vibepollo's `playnite_focus_*` settings (attempts, timeout, stop at the first success). Fullscreen mode starts again when Playnite closes after a game. A cover chosen in the console for a Playnite game is set in Playnite too (`/api/playnite/cover`), and `/api/playnite/launch` restarts Playnite. |
| Lossless Scaling | Implemented | The app's `lossless-scaling-*` fields become Vibepollo's "Vibeshine" profile for the game's programs; Lossless Scaling is restarted and its hotkey pressed (or auto scale with `lossless_scaling_legacy_auto_detect`), and closed with the profile removed afterwards. Frame generation holds the game at the app's limit or half the target. Vibepollo's 10-second CPU and peak-memory scoring selects the game, including its folder, launcher, executable and Windows-process adjustments. Scored game windows are followed throughout the session; a changed process (including a restart with a reused PID) rewrites the profile and restarts scaling. Fake-process tests cover selection and re-targeting; a real Lossless Scaling is the next check for its hotkey and window handling. |
| Frame limiting | Implemented; RTSS service cap verified | RTSS and NVIDIA profiles, game-provided frame generation, NVIDIA Smooth Motion and Lossless Scaling frame generation. rc.5 replaces RTSS's user-helper reply files in the protected service directory with private pipes and handles RTSS's profile file lock. The installed SYSTEM service applied a live 59.94 FPS RTSS cap on the RX 7900 XT, confirmed by an independent SDK read and renderer timing. rc.25 runs the RTSS SDK helper as SYSTEM in the user's session, as Vibepollo calls RTSS. Limiter ownership is separate from retained displays so disconnect restores and resume reacquires it. |
| Web console | Rebuilt | A new console (Svelte) covers overview, library (with Steam and Playnite), devices, settings, logs, maintenance and API tokens, and per-app Lossless Scaling. `/api/browse` and `/api/apps/{uuid}/icon` (an app's Playnite icon) answer as in Vibepollo. A file picker over `/api/browse` fills an app's command and working directory and the Lossless Scaling and RTSS paths. |
| Service and setup | Same | `setup.exe` upgrades a Vibepollo installation in place (drivers, service, firewall, shortcuts) and can uninstall it. The service restarts the host after a crash. `--creds` sets the console sign-in. The service's credentials folder is limited to SYSTEM and Administrators at every start. |
| Tray | Same | Open, check for updates, disconnect, quit the running app, restart and quit; notifications for pairing requests, paired devices, new versions and an app launching, pausing, resuming and stopping; the icon shows whether an app is streaming or paused. As in Vibepollo, auto-detach keeps the stream open when the app exits in under five seconds (after any wait-all children finish); a nonzero exit shows "Launch Error" with the app and exit code, and clicking it quits the app and stream. The decision, threshold and notification wording are unit-tested. |
| Updates | Implemented | Notifies first by default, with opt-in automatic installation. Downloads the exact Windows installer from the official GitHub release, verifies its size and SHA-256 digest, waits for one minute without active/pending sessions, remote monitors or host apps, and upgrades through the installed service. Failed copying/startup restores previous package files. Portable builds retain release-page downloads. Release candidates follow the existing prerelease opt-in. |
| Logs and support | Same | Rotating logs (`log_path`), live tail in the console, crash dumps and support bundle. |

## Evidence

- Automated checks (2026-10-09): `fmt --check`, `clippy --workspace --all-targets -- -D warnings` and `test --workspace` pass with **589 Rust tests**, plus 30 release-script tests and the web console and video-settings tests. The rc.10 suite included eleven HDR-state tests that distinguish explicit HDR from wide-gamut SDR and six hotplug tests that cover inactive alternatives, clone/mode preservation, target replacement, concurrent topology changes and deadlines.
- The final rc.10 host passed default-path SDR freshness at 59.999 distinct FPS and native virtual-HDR pixel checks for HEVC/AV1 at 720p60. Both HDR cases verified active HDR, FP16 capture, independently decoded ten-bit pixels and unchanged color thresholds. Eleven topology samples per run, pre-cancel checks and teardown confirmed the intended active displays and restoration. Full provenance is in [PERFORMANCE.md](PERFORMANCE.md#final-native-virtual-hdr-pixels-excluding-physical-panel-calibration).
- Native touch validation passed on the installed signed VHF driver 0.1.0.39, matching the rc.9 package. The test sent controller-touch packets through the production decoder and gamepad path into one owned DS4 and one owned DualSense in sequence, then inspected their HID reports. It verified independent primary contacts, unchanged primary state after secondary-pad down/move/up/cancel events using the same pointer IDs, rejection of a third contact when both slots were occupied, tracking identity through movement and slot reuse, cancel-all, and removal of each owned device. A pad that announces one touchpad ignores secondary-pad packets; a client that announces two has its second touchpad placed on the right half of the surface, with unit coverage and the hardware test `two_announced_touchpads_share_one_native_surface_side_by_side`.
- Exact released Moonlight PC 6.2.0 command-line behavior was isolated against the unchanged rc.9 host (`d22e446dd103592c09cd9bf11da3a76d355ab1783a18862d5d3b9f8b31a3237a`). Plain `Moonlight.exe list HOST` and CSV listing with cached artwork exited normally; three successive app-launch/quit checks and an already-idle quit also exited normally, without forced termination or window-close assistance. Paired HTTPS `/serverinfo` changed from the correct running app to `currentgame=0`/`SUNSHINE_SERVER_FREE`, agreeing with the web API. These checks used an isolated software-only host profile and a private client desktop, with no RTSP stream or live input.
- Moonlight PC 6.2.0 [crops RDNA3's AV1 padding](https://github.com/moonlight-stream/moonlight-qt/blob/v6.2.0/app/streaming/video/ffmpeg.cpp#L1772) back to the negotiated size, and its [D3D11 renderer uses the cropped dimensions](https://github.com/moonlight-stream/moonlight-qt/blob/v6.2.0/app/streaming/video/ffmpeg-renderers/d3d11va.cpp#L819). Three exact-client checks passed: 1920×1080 SDR and HDR, and 1968×2184 SDR. Client logs confirmed the coded sizes, eight/ten-bit decoding, cropping to the negotiated dimensions and D3D11 rendering, with no decoder errors.
- October 5 rc.4 helper: 188 ordinary workspace tests pass, including five transport/ownership checks. Seven local 720p60 motion cases cover direct WGC, the helper, HEVC, AV1, HDR output from an SDR source and compute disabled, all at 60 fresh pictures per second without decode errors. Forced helper termination reopened WGC in 357 ms; all 1,249 received pictures decoded. After a normal installer upgrade, the SYSTEM service launched the helper as the signed-in user and captured a 2184×1968 native HDR virtual display for an AV1 120 FPS session with compute enabled at both ends. The client confirmed correct pictures and responsive input.
- October 5 final workspace/native run: 200 pass, including 20 opt-in native checks, on an active moving desktop, among them WGC compute synchronization and same-frame fallback after a sharing failure. Clippy with warnings denied and the web console's type check pass.
- Native AMD tests on the test PC: GPU colour and letterbox conversion, cursor composition, AMF loss recovery, Opus surround, WGC teardown, and the software encoder letterbox test.
- Independent wired LAN receiver on the Intel NUC: H.264 and WGC/HEVC at 1080p60, HEVC HDR and aligned AV1 at 720p60, exact decoded geometry, pixel contrast and nonzero Opus audio. A 230-second HEVC stream decoded 13,838/13,838 pictures and continued fresh capture claims beyond the display's idle timeout.
- Live on the test PC with the installed service: phone streaming at 1968x2184, 120 Hz, HDR, on a per-device virtual display; two clients streaming at once on their own displays; capture recovery after a lost Desktop Duplication session; OTP pairing; the installer upgrading the Vibepollo installation in place.
- Radeon 780M laptop over Wi-Fi with Moonlight 6.2.0: six HDR stream formats at native, 1440p120 and 1080p60, render-to-received picture age recorded for each ([Performance](../docs/performance.md#on-a-real-client-over-wi-fi)), and AV1 loss recovery with 59 of 59 lost frames recovered without a keyframe.
- Moonlight for Xbox: HDR streaming at 3840×2160, 120 Hz, HEVC.
- Steam: discovery of 17 installed apps across three libraries, appinfo names and types, play history, covers (including store downloads), and a sync that adds the apps once and then reports no change.
- Playnite, through the plugin's protocol: plugin install, library sync with a converted cover, a launch that passes the stream's 88 environment variables and ends on `gameStopped`, and closing the app mid-game.
- Lossless Scaling: the profile names the game's program and is removed when the app closes.

## Reproducible verification

An optional [Moonlight 6.2.0 source patch](compatibility/moonlight-6.2.0/README.md) addresses the cold-cache CSV worker path. Eight focused real-Qt Linux cases passed and three negative controls exposed the original behavior.

```powershell
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test -p butterpollo-windows --locked -- --ignored --skip native_nvenc_loss_recovery_and_444_hdr_decode --skip native_av1_geometry_and_hdr_are_preserved --skip primary_multitouch_and_secondary_isolation_match_native_hid_reports --skip two_announced_touchpads_share_one_native_surface_side_by_side --test-threads=1 --nocapture
```

The native command needs the packaged codec DLLs on `PATH`, an AMD D3D11/AMF adapter, working interactive WGC, a moving desktop and a local network route; it does not change display modes, audio defaults or the installed service. `motion_probe DISPLAY SECONDS REPORT.json current 128` can provide movement on an explicitly selected active output without changing its mode. Set `BUTTERPOLLO_TEST_OPUS_ROOT` to the packaged runtime directory, `BUTTERPOLLO_TEST_FFMPEG` to an independent FFmpeg decoder and `BUTTERPOLLO_TEST_RFI_REPORT` to a report file.

The separately selected `primary_multitouch_and_secondary_isolation_match_native_hid_reports` and `two_announced_touchpads_share_one_native_surface_side_by_side` tests require the signed VHF driver and an idle input session. They create and remove owned neutral DS4/DualSense devices; they are excluded from the codec command above.

On an NVIDIA host with a display attached to that adapter:

```powershell
$env:BUTTERPOLLO_TEST_NVENC = '1'
$env:BUTTERPOLLO_TEST_NVENC_REPORT = 'C:\path\to\artifacts\nvenc.json'
$env:BUTTERPOLLO_TEST_FFMPEG = 'C:\path\to\ffmpeg.exe'
cargo test -p butterpollo-windows --locked native_nvenc_loss_recovery_and_444_hdr_decode -- --ignored --test-threads=1 --nocapture
```

`tests/web_api.py`, `tests/console_browser.cjs`, `tests/session_restart.py`, `tests/interop.py` and `tests/otp_pairing.py` run against isolated test-owned profiles and stop only their own processes. See [PERFORMANCE.md](PERFORMANCE.md) for measurements.
