# Background streams: game sound and focus
- **A background stream's game no longer plays on the PC too (#59).** 3.4.0 moved the game to the virtual playback device as it started, before the game had opened its sound. Windows refuses that for every game ("The parameter is incorrect"), so the sound stayed on the PC's speakers. Rubylight now moves the game once it opens its sound, trying again after half a second, then less often. A game that plays on Windows' default device moves at once; one that opened a particular device keeps it until it next starts, and the stream says so. Tested on this PC's Windows 11 build 26200, from the host's own SYSTEM account and from the user's: the move is refused before a test process opens its sound and accepted after, a stream on the default device moved to Steam Streaming Speakers and back, and a stream opened on a particular device stayed.
- **A game that refuses Nucleus Co-op's input hooks takes the controller from the start (#59).** Such a game, Assassin's Creed IV: Black Flag Resynced for one, reads its controller only while its window is in front, and it waited for a click on its taskbar icon on the PC. Rubylight now brings its window to the front once as it opens, unless someone uses the PC. The person at the PC can click back to their own window.
