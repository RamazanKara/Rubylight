# Settings reference

[Documentation](index.md)

This page is the reference for every setting in Nightjar for Android, Android TV and Fire TV, followed by [Nightjar for Windows and Linux](#nightjar-for-windows-and-linux). Both clients use the same sections, **Video**, **Display & image**, **Controls**, **Audio**, **Streaming**, **App**, **Advanced** and **Debug** at the end for settings whose default is right for nearly everyone, and the same layers of values: the main settings, a [named profile](#named-profiles-and-game-settings), [this PC](#per-pc-stream-profiles) and this game.

Each row shows its current value; the explanation appears with the setting or behind its info or **Help** button. Search matches titles, explanations and section names, including everything in **Advanced**. Selecting a result opens its section, and Back returns first to the search, then to the section where you started. Changes save automatically. Nightjar shows only the options the device supports.

On a TV, and on screens at least 840 dp wide, Settings uses two panes: sections on the left, the selected section on the right. Moving the D-pad or controller over a section shows it on the right at once; Center or Right moves into it, Left or Back returns to the list, and Back from the list leaves Settings. Touching a section shows it without moving focus. The list starts with **Search settings**, a focusable row (also on phones with a controller attached); results fill the right pane. On a TV, focus starts on **Controls**, never on the toolbar. Links from other screens open the setting they name, selected and, with two panes, focused.

**Profiles**, **Controller buttons**, **Keyboard shortcuts**, **GPU driver** and **Latency benchmark** put the first focus on their content when a remote, controller or keyboard drives them. Every focused button or row shows the same amber outline.

Defaults are those of a fresh installation, before any preset or PC override. Changes to stream settings apply from the next stream; the stream menu holds the controls that can change during a session.

The tables between the markers below are generated by [generate-settings.py](../scripts/generate-settings.py) from [preferences.xml](../app/src/main/res/xml/preferences.xml), the English strings and arrays, and the Java defaults and preset values. Regenerate them after changing preferences instead of editing rows by hand; the [documentation checks](building.md#documentation-checks) detect stale output.

## Global settings

These tables include every preference, including actions, grouped as the Settings screens show them. On/Off choices have no units; action rows have no stored default. Device capability checks can hide or disable a row.

Tier: Main rows show when a section opens; More rows fold behind the section's last row, More … settings, and search still finds them (`res/values/settings_tiers.xml`).

#### Refresh rate

| Setting / preference key | Tier | Default | Choices and units | When to change or use |
| --- | --- | --- | --- | --- |

| Allow lower refresh rate<br>`checkbox_reduce_refresh_rate` | More | Off | On; Off | Enable to allow a lower screen refresh for power savings. Shown while Variable refresh rate is Off. |
| Match the screen to the game’s frame rate<br>`checkbox_content_rate_frame_rate` | More | Off | On; Off | Enable on a screen with several refresh modes, with Allow lower refresh rate (or a Balanced with FPS limit or Smoothest video pacing) on. | Take back display queue delay<br>`checkbox_display_queue_recovery` | More | On | On; Off | On by default. ## Named profiles and game settings

A named profile is a set of stream values with a name, such as *Home 4K120*, *Hotel* or *Mobile data*. Open **Settings → Profiles** (under the presets) to manage them. Implementation: [StreamProfilesActivity.java](../app/src/main/java/com/limelight/preferences/StreamProfilesActivity.java), stored by [StreamProfiles.java](../app/src/main/java/com/limelight/preferences/StreamProfiles.java) and combined by [StreamLayers.java](../app/src/main/java/com/limelight/preferences/StreamLayers.java).

### Which value a stream uses

When a stream starts, each value comes from the first of these layers that sets it:

1. **This game**: the game's own values on this PC (game menu → **Stream settings for this game**).
2. **This PC**: the PC's own values (**PC settings…**, see [per-PC stream profiles](#per-pc-stream-profiles)).
3. **The profile**: the profile the network picked, or else the profile in use.
4. **The main settings**: everything under **Settings**.

On mobile data, **Bitrate on mobile data** then caps the bitrate, whatever layer set it. A layer that sets nothing leaves every value to the layers below. Profiles, PC and game values apply when a stream starts and never change during it; a reconnect keeps the network, and so the profile, that the stream started with.

Every value screen says where a value it doesn't set comes from: *from the main settings*, *from profile Hotel*, *set for this PC*. The Debug overlay and the Statistics status line show which layers a stream used, for example *Settings: profile Hotel, chosen for Mobile data + this game*. A profile picked by the network is also announced when the stream starts.

### Profiles

### Fallbacks

Nothing falls back silently. When the profile picked no longer exists or has a value this version can't read, the main settings apply and the stream says which profile was skipped. When a PC's or a game's stored values can't be read, that layer is skipped with a message and the layers below apply.

### Game settings

Open a game's menu and choose **Stream settings for this game**. The note under it says how many values the game sets. The screen has the same stream rows as a PC, plus the PC's virtual display rows (**Virtual display**, **PC render resolution**, **PC display scaling**) where the host has them; the display arrangement stays per PC. Values not set come from this PC, the profile and the main settings, in that order. Removing a PC removes its game values too.

A game's screen starts with a **Preset** row. Each preset sets only the values it names and leaves every other value of the game as it was, including the other two of frame pacing, variable refresh rate and bitrate. Nothing new is stored: the row names the one preset whose values the game holds, and says Custom when none matches, when two presets' values are both present (Smoothness with Quality, for example), and for a game with no values of its own. Resolution, refresh rate, codec and HDR are never touched.

| Preset | Sets | Leaves alone | Trade-off |
| --- | --- | --- | --- |
| Competitive | Frame pacing: lowest latency (the app default, set for this game so it holds if the main setting changes) | Variable refresh rate, bitrate | No extra delay. |
| Smoothness | Frame pacing: smoothest video; variable refresh rate off for this game, because it replaces frame pacing | Bitrate | Frames are held back, so latency goes up. |
| Quality | Bitrate: 150% of the PC's bitrate, or of the main settings' if the PC has none, at most the host's maximum (2000 Mbps) | Frame pacing, variable refresh rate | On a weak connection the larger frames can add delay. The bitrate is stored as a number, so a later change to the PC's or main bitrate shows the game as Custom. A named profile or the network never changes the base. |
| Custom | Nothing | Everything | Set each value yourself. |

Presets never change Radeon settings such as Anti-Lag and Chill; set those for a session in the [Session and graphics](console.md) menu.

### Bitrate on mobile data

**Settings → Video → Bitrate on mobile data** (Off, 3, 5, 10, 15, 20, 30 or 50 Mbps) caps the bitrate of a stream that starts on mobile data or metered Wi-Fi. It is separate from the profiles, so it protects a data plan whatever profile, PC or game value applies. The cap is decided at stream start; switching networks during a stream doesn't change it.

### PC, game and profile settings

A PC's, game's or profile's settings show the same rows, except the App section, **Graphics card**, **Renderer**, **Bitrate on mobile data**, **Input-only on any PC** and the rows that open other pages (**Controller buttons**, **Controller test**, **Keyboard shortcuts**, **Stream hotkeys**); Debug stays last. Each row has a box, **For this PC**, **For this game** or **In this profile**: ticked, the row keeps its own value and says what it would otherwise be; unticked, it says where its value comes from (**From main settings**, **From profile …**, **Set for this PC**). Choosing another value ticks the box; opening a menu and backing out changes nothing. The section list counts the rows set there, and **Clear all for this PC** (or game, or profile) at the top unticks every row after a confirmation. A PC's own settings also run **Connection test** (Streaming) and **PyroWave frame pace** (Advanced › Diagnostics) on that PC. The layers combine as on Android; see [which value a stream uses](#which-value-a-stream-uses).

**Profiles**, above the sections in the main settings, opens the profiles page; while a profile is active, the main settings say so at the top, with **Manage profiles**:

| Control | What it does |
| --- | --- |
| Active profile | The profile streams use, or **Main settings**. While a profile is active, the main settings say so at the top. |
| New profile | Asks for a name and opens the new, empty profile's settings. |
| Choose automatically | Picks a profile when a stream starts, by network: **Mobile or metered**, **Home Wi-Fi** and **Other Wi-Fi**. A network left at **Active profile** follows the active profile. |
| Home Wi-Fi names | **Add** a typed name, or **Add current Wi-Fi**; **Remove** takes one off. Up to 50 names of up to 32 characters; names are case-sensitive and stay on this device. |
| Mobile data bitrate limit | 0–500000 kbps; 0 means no limit. Caps the bitrate on mobile data and on metered Wi-Fi or Ethernet, after all profile, PC and game values. **Video → Bitrate on mobile data** sets the same limit. |
| Saved profiles → Edit / More | Edit opens the profile's settings; More holds Rename, Duplicate and Delete. |

Settings are stored in `settings.json` in `%APPDATA%\Nightjar\config` on Windows, `~/.config/nightjar` on Linux or `~/Library/Application Support/Nightjar` on macOS; `NIGHTJAR_CONFIG_DIR` overrides the folder.

Defaults are those of a fresh installation. **Main** rows show when a section opens; **More** rows follow behind **More … settings**, under the group named in italics, in the order shown.

Both are off by default and are set with the `beam_race` and `early_decode` keys in `settings.json`, or the `NIGHTJAR_BEAM_RACE` and `NIGHTJAR_EARLY_DECODE` environment variables; see [beam racing](beam-racing.md) and [early decode](early-decode.md).
